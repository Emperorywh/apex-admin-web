# SPEC：框选同向路径拆分（拓扑同向 / 方向同向，v3）

> 状态：已实施
> 日期：2026-08-28
> 前置规格：[SPEC_brush_same_direction_contextmenu.md](./SPEC_brush_same_direction_contextmenu.md)（v2，右键菜单 + 显式基准）。v2 的显式基准、一次性模式生命周期、右键交互、基准失效防御等机制对拆分后的两个模式**均成立**，本规格只记录拆分差异；v2 文首已加"部分拆分"标注。
> 更早规格：`docs/SPEC_brush_same_direction.md`（v1，整体废弃；其 §10 几何同向算法是本规格"方向同向"的历史前身，但判定口径已由"夹角 ≤ 90°"收紧为"角度完全一致"）

---

## 1. 背景与目标

v2 把「框选同向路径」做成单一入口 + 单一拓扑语义（双向 BFS），U 形汇聚段（拓扑不连、视觉同向）按决策回退为"选不中"（v2 §4.5 / 验收 #15）。实际使用中，"把框内所有与基准方向完全一致的平行边选出来"是独立于拓扑连通的真实诉求（平行车道、多楼层同向通道）。

因此把原菜单拆为两个并列入口：

| 菜单项 | manualKey | 同向语义 | 算法 |
| --- | --- | --- | --- |
| 框选拓扑同向路径 | `brushSelectSameDir`（沿用 v2 key） | 沿 snode→enode 首尾相接、顺流/回溯可达 | 拓扑双向 BFS + 全局折返守卫（v2 原样） |
| 框选方向同向路径 | `brushSelectSameAngle`（新增） | **弦方向角度完全一致**（方向角差为 0），不做连通性要求 | 弦向量归一化后 \|cross\| < 1e-6 且 dot > 0 |

示例：两条水平边 `1302`（s(14.596, 5.410)→e(15.996, 5.410)）与 `1400`（s(14.596, 4.010)→e(15.996, 4.010)），snode/enode 互不相同（拓扑不连），但弦方向同为 +x 方向——拓扑模式选不中，方向模式互为同向。

## 2. 交互（与 v2 完全同构）

两个菜单项共用 v2 的全部交互机制，逐条对应 v2 章节：

- 入口与置灰：右键边/节点/空白显示（`enable: ["node","edge","stage"]`），恰好左键选中 1 条边才可点（v2 §4.1）。
- 进入模式：基准快照写 stage attr `sameDirBaseEdge`（**两种模式共用**，模式由 manualKey 区分）+ `message.info` + 十字光标 + 基准保持高亮（v2 §4.11 / §6.4）。
- 一次性生命周期：有效框选后自动退出；退化框选（<2px）/拖出画布保持模式可重框（v2 §4.2/§4.3）。
- 结果集：命中筛选结果 ∪ {基准}，基准放首位（v2 §4.4）。
- Ctrl 不特殊处理（v2 §4.6）；模式期间左键点击屏蔽（v2 §4.7）；右键静默退出 + 照常弹菜单（v2 §4.8）；基准失效提示（v2 §4.9）。
- 遍历/命中只算可见边；命中检测在屏幕坐标系（沿用 `findShapesInRect`）。

### 提示文案差异

| 时机 | 拓扑模式 | 方向模式 |
| --- | --- | --- |
| 进入模式 | `请框选区域，将选中与【基准名】拓扑同向的路径` | `请框选区域，将选中与【基准名】方向同向的路径` |
| 命中非空但无同向 | `未找到拓扑同向路径`（带相邻候选特判，v2 §4.10） | `未找到方向同向路径`（无特判，见 §3.3） |
| 基准失效 | `基准路径已失效`（共用） | 同左 |

## 3. 方向同向算法（`selectSameAngleEdges`）

`src/utils/sameDirectionEdges.ts` 新增纯函数 `selectSameAngleEdges(baseEdge, hitEdges)`，签名与拓扑模式一致（基准与命中集合分离传入）。

### 3.1 弦方向口径

- 弦方向 = snode → enode 的直线向量，**不读控制点**，贝塞尔/直线统一处理（与 v1 §10.3 同口径）。
- 数据 y 与画布 y 反向（`worldToScreen(sx, -sy, stage)`），视觉向量取 `dx = ex - sx`、`dy = sy - ey`（v1 口径）。相对比较下取哪一侧只影响整体符号，沿用 v1 注释口径。

### 3.2 "角度完全一致"判定

- 两向量各自归一化后：`|cross| < 1e-6 && dot > 0` ⟺ 方向角差为 0。
  - `cross` = sin 方向角差（无量纲，与边长无关）；`dot > 0` 排除反向共线（A→B 与 B→A 角度差 180°，不算同向）。
  - EPS = 1e-6（约 0.00006°），仅容忍浮点噪声，用户感知为"完全一致"。与 v1 的"夹角 ≤ 90°"（点积 > 0）不同：斜向、垂直、反向全部排除。
- 两个方向同向算法都在数据坐标系下比较，与 stage 缩放/旋转无关。

### 3.3 边界

| 场景 | 行为 |
| --- | --- |
| 基准零长度边（sx==ex 且 sy==ey） | 弦方向无法定义 → 结果仅基准；命中非空时提示「未找到方向同向路径」 |
| 候选零长度边 | 弦方向无法定义 → 排除 |
| A↔B 双向段（基准 A→B，框住两条） | 反向边角度差 180° 天然排除 → 结果仅基准 + 提示（**无** v2 §4.10 的相邻候选特判——方向模式的语义就是纯角度，提示有助于理解） |
| 基准不在框选区域内 | 仍进结果（与 v2 §4.4 一致） |
| 仅框住基准自身 | 不提示（基准与自身角度恒一致，v2 §4.10 同判据） |
| 框到空区域（0 命中） | 有效框选：结果 = 仅基准，不提示，模式退出（v2 §4.10 同判据） |
