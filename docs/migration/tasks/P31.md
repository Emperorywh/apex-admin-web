## 接口缺口 / 契约发现

- **addUser 形态对照**（contracts 第 5 节登记）：OpenAPI AuthUserAddParam 仅 username/password 两字段；联验多轮实证两字段与三字段（+confirm，MD5 同值）后端均受理，confirm 提供时后端校验一致性（不一致 500「失败」）。按等价迁移保留旧实现三字段形态。首轮两字段曾 500 无详情、复测不复现——**G20 扩展第二例**（后端暂态 500，gaps.md）
- **pageUsers 响应含 password 字段**（安全观察项，gaps.md 新登记）：列表每行返回 password（MD5 摘要）+level 字段；旧实现同源未展示；新页面 DTO 类型保留完整但 UI 不消费不展示；建议后端脱敏，待后端确认
- 业务码实证：1000140 用户已经存在（重复名）/1000130 用户名格式不正确（连字符名，API 直调触发，前端 pattern 校验先行用户不可达）/1000000 无令牌（pageUsers、addUser 双通道对照）
- updateState 按	username 定位（OpenAPI AuthUserUpdateStateParam 同），非按 id——与页面「按行 id 提交其他操作」不同源，等价旧实现
