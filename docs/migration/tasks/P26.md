## 4. 接口缺口与登记

- **契约变更（联验实证，非缺陷）**：新后端 `getSystemLogTypes` 返回模块名集合
  `['vehicleState','auth','device','dispatcher','driver','imap','system']`，旧版默认
  `logType='NORMAL'` 已不在集合（查询 total=0）；且缺 logType 后端亦返回空 data
  （logType 实为必传条件）。**处置**：默认类型改为「集合就位后取第一项」（不写死
  不臆造），起始查询延迟到默认值就位（类型未加载时 request 不发业务查询），保持
  旧版「打开页面即见数据」交互语义；契约登记 contracts 第 5 节系统日志行。
- **请求层修复（公共文件，影响已核）**：`responseType:'blob'` 通道收到 JSON 业务
  错误时（如本页 7000130「导出的系统日志文件为空」，且错误响应仍带
  content-disposition 附件头，极易误存为伪文件），拦截器把 Blob 按文本读回解析后
  走统一 `unwrapResult`——真实业务码/消息如实抛出，绝不落伪文件（DoD 9）。修复前
  该场景误报「响应不符合调度协议（缺少 Result 包装）」。消费者影响：Blob 下载通道
  全部消费者（P03 导出/P08 下载/P09 下载/P25 下载/P26 下载）仅错误路径文案变化
  （真实业务消息替代协议错误泛文案），成功路径（非 JSON content-type）不受影响；
  lint/typecheck/build 全绿 + 本页浏览器层下载成功链路复验通过。
