## 3. 契约发现（联验实证）

1. **重名新增 → 5000000「车辆动作组名称已经存在」**：组名唯一性约束在后端（前端弹窗未做重名预校验，旧实现同边界；提交后端拒绝如实反馈）。
2. **删除被引用动作 → 5000010「车辆动作已经关联了车辆动作组」**：后端动作↔动作组双向引用完整性——「组内失效动作」的自然路径不可达（动作被组引用时后端拒绝删除动作）。前端失效识别保留为防御性实现（P23 未知枚举 options 并入同款处置）。
3. **update.agvActionIds 含不存在动作 id → 后端 200 受理但静默过滤**（实测提交 [2,99999] 落库后组内只剩 [2]）：**前端失效拦截的存在价值实证**——若不拦截，含失效项的保存会被后端静默瘦身，用户已选动作无声丢失（违反「失效动作保留原标识」）。
4. **拖拽重排与弹窗编辑共用 updateAGVActionGroup**（同 operation 同 body 形态）——API 层以一次链路覆盖两条 UI 路径的协议验证。
