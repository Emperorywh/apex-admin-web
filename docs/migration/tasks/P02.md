## 交付内容

1. **服务层**（`src/services/license-activation/license.service.ts` + `.types.ts`，P29 共用）：
   - `fetchHardwareInfo()`：GET `/auth/license/getHardwareInfo`（ResultString）。真实环境 GET code=200 实证可用、不要求认证（授权页作为登录落点必须可用）。
   - `activateSoftware(activationCode)`：POST `/auth/license/softwareActivation`（SoftwareActivationCode → ResultVoid）；写操作不自动重试，结果以业务 code=200 判定。OpenAPI security 均 None，认证头由请求层按会话统一携带。
2. **可复用激活业务组件**（供 P29）：
   - `features/license-activation/components/ActivationForm/`：激活码输入+提交+loading 防连点+失败保留输入+真实成功反馈；`onActivated` 回调由调用方决定导航（P02 落点规则/P29 原地刷新）；可选 `onBack` 渲染返回登录（P29 不传即无）。组件不感知硬件码展示与路由/会话。
   - `features/license-activation/hooks/useHardwareInfo`：加载/失败(可重试)/成功三态，卸载取消、防乱序、失败不以空串冒充成功（DoD 6）。
   - `features/license-activation/utils/copyText`：安全上下文 Clipboard API + 内网 http execCommand 兜底（旧系统已证实行为）。
3. **页面**（AuthorizeIngress.tsx + .module.css）：旧深蓝科技风等价移植（网格/扫描线/四角边框/水印，含 prefers-reduced-motion；独立页固定深色与旧系统一致）；硬件码展示+一键复制；图标 lucide 对齐目标项目；「SOFTWARE LICENSE ACTIVATION」英文小标为固定装饰文案（旧系统同款，不随语言变化）。

## 登记的限制与待验收（非缺口）

1. **激活成功链路（写副作用）**：专用环境验收——提交真实激活码 → 成功提示 + activated 更新 + 落点导航。当前两个可用后端均为已激活态，提交无效激活码的写尝试不对共享环境执行。
2. **activated=false → 登录落点授权页**：真实触发待未激活环境（机制=T00.4 实证 + resolveLandingPath 代码分支；本轮曾在 10.11.2.67:8888 复试，该环境现已 activated=true/25 角色）。
3. **1001000 真实业务触发**：待未激活环境 + 首个发业务请求的已迁移页（P03/P05）；接线本身已实证（事件→导航、授权页抑制、单飞标记）。
4. **授权失效（到期）业务码**：仅实证 1001000=未激活；到期如以其他码表达则走通用业务错误分支（显示后端 message），随 P29 getLicense 联调复核。
5. **激活码长度上限 2000**：前端输入卫生约束（旧页面无上限），如专用环境发现更长合法码需放宽。
6. **dev 服务器缓存假象（非产品缺陷）**：同秒内对 App.tsx 的两次编辑使 Vite dev 转换缓存提供过中间版本（有 import 无 JSX），一度表现为事件不跳转；生产构建（preview 4173）验证接线正常。复现规避：同文件连续编辑后 touch 或清 `node_modules/.vite`。
