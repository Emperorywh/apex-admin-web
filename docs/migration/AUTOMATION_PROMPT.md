# 调度系统迁移：定时任务提示词

你负责持续推进 `C:\code\apex-admin-web` 的调度系统迁移。每小时由外部定时器触发一次；本轮只处理一个任务，不派生开发 Agent，不自行循环或创建定时任务。使用固定项目目录及 RUN_STATE 约定分支。

## 开局与依据

先读当前 AGENTS.md、TASKS.md §1–4 和当前任务卡、完整迁移规格 `docs/SPEC_dispatch_migration_20260917.md`、RUN_STATE、当前任务与必要前置交接记录。用户最新决定优先；历史交接记录只提供事实，不能修改规格或自行豁免验收。未变化的规格可以复用已读内容，但须核对文件哈希；新会话仍须完整阅读。禁止新增单元测试、无关格式化及未经要求升级依赖。

先执行 `node scripts/migration-runner.mjs status`。定时任务不自动恢复遗留锁：锁存在时只核验对应运行，仍在执行或无法证明已经结束就结束本轮，不改代码、台账或锁。不得凭时间、心跳或临时 shell 进程消失接管。确有对应会话终止证据或用户明确确认后，按 TASKS §2 的 recover 流程保留证明再恢复。

以 status 给出的 next 为本轮任务与 purpose。历史状态/证据不一致优先做该任务的 audit，复用已有代码与持久证据，不重新开发整页。非复核轮恢复当前任务，不挑容易任务，不跳过受阻任务。先取得锁：`node scripts/migration-runner.mjs begin --run <唯一运行ID> --session <实际会话ID> --task <任务ID> --purpose <audit或implement或acceptance或delivery>`。收到成功后才可以修改项目；开始前保存的 Git 状态是用户修改保护基线。

## 实施与放行

保留现有 MacOS 外壳、技术架构和官方 npm ApexTableReact，禁止二次封装表格。递归核对旧路由实际可达组件，完成当前任务内的服务、DTO、权限、页面、子表、表单、文件、生命周期及五语言。新增或修改代码写多行简体中文注释。你同时负责本任务集成，可修改必要公共文件，须列消费者并验证影响；不借机开发后续页面。

分开记录 implementation、verification、gate、publish。每轮最多一个任务，包括只做验收复核的轮次；本轮完成检查点、放行或验收后即结束，下一项留到下轮。

只有实现完整、静态门禁、真实只读、当前页面 UI 和公共消费者核验均满足，才允许 gate=ready。TASKS §3 已规定的跨页补验、专用环境/现场副作用验收、已确认接口缺失可以登记明确的条目、依据、负责人、解除条件和消费者影响后放行；不能把普通缺陷、样本不足、浏览器脚本失败、未经核实的接口或可在本任务修复的问题当例外。影响消费者的缺口必须阻塞消费者。P03/P05→P38/P39、P34→P36 等跨页补验按 TASKS 既定责任执行，不要求前项先勾选。

verification=passed 必须覆盖全部适用 DoD、任务卡及 A/I 条目，且无待验收项；只有此时 TASKS 才勾选。记录缺口不等于通过，前端实现完成不等于整体迁移完成。历史勾选迁为待复核保留原实现进度，不代表需要重做代码。

## 验证与证据

执行适用的 `pnpm check`、`pnpm build`、真实只读和浏览器验收；没有代码或条件变化不重复全量检查。查询性质 POST 按业务语义分类。静态全绿不能替代真实页面；记录代码提交及受检文件哈希、后端实例、数据规模、角色、视口、主题、语言、步骤、预期、实测和验收编号。

后端写验收必须有明确授权的专用环境、允许 operation 和自有测试对象，未满足则只实现前端及验证确认/取消路径。不得自动执行现场创建、删除、车辆控制、地图推送、重启、回滚；“零净变化”不能作为无副作用证明。写请求超时先查询实际状态，不自动重放；清理只操作本轮记录了真实标识的自有测试对象。

新证据和不含凭据的验证脚本持久保存到 `docs/migration/evidence/<任务ID>/<运行ID>/`。测试截图放在其 `screenshots/` 子目录，仅本地留存，禁止提交 Git、强制添加、打包或内嵌图片绕过。Git 只保存文字记录、验证脚本和注明 `local_only`、相对路径、SHA-256 的索引；其他环境缺少本地原图时如实说明证据不可复核。不得把唯一证据放在临时 .run-lock 或验后删除。凭据从本机既有安全来源读取，记录中只留来源名称，不存密码、完整 token、Authorization 或 Cookie。旧归档证据明确标记历史记录，未经复核不能算新通过。

使用 rAF/ResizeObserver 垫片、合成事件、直写存储或绕过交互时，说明覆盖范围；这些手段不能证明被绕过的真实用户交互正常。真实指针、自然浏览器、不同平台未覆盖项如实保留。

验收记录按 TASKS §2 定义的 JSON 保存，并用 checkpoint 提交状态。重要步骤及时保存：`node scripts/migration-runner.mjs checkpoint --run <运行ID> --revision <当前修订号> --file <仓库内检查点JSON>`。禁止直接覆盖 RUN_STATE；修订号冲突先重读，禁止盲目重试。

## 提交、推送与结束

自动提交并推送本任务经审查的代码、交接、文字证据及验证脚本到 RUN_STATE 约定的远程分支；测试截图不提交，不得夹带开局已有的无关修改。逐文件或逐块暂存，不使用未经审查的 git add -A，不强推、不重置、不自动处理分叉，不部署或修改后端。提交前检查凭据与证据脱敏，并确认暂存区没有测试截图。

提交后执行 `node scripts/migration-runner.mjs push --run <运行ID> --commit <已审阅HEAD完整哈希>`；脚本先查询远端再决定是否补推，并再次确认远端提交。失败记 publish=blocked，后续轮先用 delivery 恢复，未恢复不领取后续开发。RUN_STATE 的推送回执允许作为下轮开局的已知变更，不为把回执写进它自身的提交而无限追加提交。

受阻时先完成本任务内不受阻的部分，记录原因、尝试、解除条件和最小复查方法。条件未变化时轻量检查后退出，不重复写同样的记录、不重复失败实验、不伪造新进展。

结束使用 `node scripts/migration-runner.mjs end --run <运行ID> --outcome <completed或checkpoint或blocked>`，它先保存结束记录，再只释放自己的锁。异常中断不承诺 finally 一定执行，下一轮必须走有证据的恢复。completed 只表示本轮正常结束，不改变任务验收状态。所有任务最终验收通过且交付确认后，后续触发只核对并结束。

最终仅在有实际进展、交付完成、新阻塞、状态不一致或需要用户处理时报告；阻塞未变化保持简短，不重复宣告完成。
