## 2. 已发现的现状与迁移约束

1. 目标项目采用 React 19、TypeScript 6、Vite 8、React Router、Redux Toolkit、axios、react-i18next、CSS Modules；保留这套架构，不迁入 Umi 运行时。
2. 目标项目已注册调度菜单，大部分页面仍是 `PagePlaceholder`；任务列表仍使用 Ant Design Table，仪表盘和任务服务存在 mock。
3. `src/services/auth/auth.service.ts` 当前任意账号密码直接放行，并生成本地超级管理员身份；必须改为真实登录。
4. 当前请求层假定 REST 路径、资源本体响应、RFC 9457 错误和 Cookie 刷新令牌；调度协议采用 `/fms/v1/...`、`code/message/data/timestamp` 包装及另一套认证约定，必须适配，不能只替换 baseURL。
5. 旧系统为 Umi + Ant Design 5，包含独立权限模型、工艺嵌套表格、行内编辑、地图选点、上传下载和设备控制。迁移需替换 Umi 路由、状态、国际化和请求依赖。
6. `apex-table-react@0.1.0` 支持 React 18/19，包含 `request`、行展开、编辑器、虚拟滚动、列偏好适配器和主题变量；包自身依赖 `antd@6.6.4`。必须验证实际安装版本的公开声明，不能假设本地尚未发布的能力已存在。
7. 当前缓存使用 React `Activity`，普通页签有 LRU 淘汰机制；草稿、轮询与长传输需要分别定义生命周期。
8. README 引用的 `docs/macos_ui_ux_design_guide_v3.md` 在勘察时未找到，视觉基线以现有布局、全局 token 和实际组件为准。
9. `package.json` 的 `check:structure` 指向当时不存在的 `scripts/check-structure.mjs`。后续实现阶段需要修复有效检查入口，不能把缺失检查报告为通过。
10. 新增、修改代码须写多行简体中文注释，解释行为与必要约束；遵循附近代码风格，不主动格式化无关文件。

## 3. 范围与信息架构

### 3.1 范围定义

旧路由共 45 个具有页面组件的叶子节点，包含登录、授权、无权限和兜底错误页。明确暂缓 3 个，其余 42 个叶子入口纳入迁移或同类合并验收，不等同于要新增 42 份独立实现。目录路由、重定向和共享弹窗同时纳入相关页面的闭环。

“所有页面”指当前 `.umirc.ts` 路由及其实际可达组件，不包括源码中没有入口的历史实现。表格替换范围覆盖目标应用最终所有可达页面，包括保留的模板公共功能。

首页将模板仪表盘与调度实时看板合并为一个业务首页。建议以现有 `/dashboard` 为规范地址，将 `/analyze-visual/dashboard-realtime` 兼容重定向到同一实例；共享权限、数据与轮询，不能出现两个重复看板。登录后优先进入首页；无首页权限则进入第一个有权限、已实现且可用的业务页；无可用业务页显示无权限或明确的不可用说明，避免循环重定向。

用户管理、角色管理、任务管理只保留一套业务入口和实现。模板个人中心等公共能力仅保留可接真实接口的部分，无法对应的资料或配置不得伪造。文档没有菜单 CRUD 接口，不沿用模板菜单管理形成虚假能力。

## 4. 前端架构与 API 适配

### 4.1 分层

保留 `pages` 页面入口、`features` 业务组件/Hook、`services` 请求服务/DTO、跨层领域类型及 `router` 单一真相源。推荐按 auth、vehicle、order、map、device、process、report、system 等业务域拆分服务。

每个服务沿用当前项目的 `*.service.ts`、`*.service.types.ts` 风格：具名函数、明确请求/响应类型、可选 `RequestOptions`、可传递 `AbortSignal`。页面不直接导入 axios、不拼业务 URL、不处理原始响应包装、不复制全局认证错误逻辑。

DTO 保留后端真实字段与枚举；服务/适配函数转换成前端易用实体。允许用规范化名称暴露 `items/total/page/pageSize`，但不得把这种内部名称错误发给调度后端。不要整体复制旧 `src/api/index.ts` 成为新的巨型服务文件。

### 4.2 协议

| 层面 | 目标规则 |
| --- | --- |
| 实际路径/方法 | 严格按 OpenAPI operation，例如 `POST /fms/v1/auth/authorize/login`；不改写成文档没有的 `/auth/login` 或 `/users` |
| 成功判定 | 区分 HTTP 与业务状态；文档 Result 说明 `code=200` 正常，不依赖 `message === 'success'` 的英文字符串 |
| 响应解包 | 统一处理 `code/message/timestamp/data`；void、列表、分页、文件各有明确类型 |
| 错误 | 统一归一化为可展示的 ApiError，保存 HTTP 状态、业务码和必要详情；非 200 业务码不能进入成功分支 |
| 分页 | 常见后端 `pageNo/pageSize` 与响应 `records/current/size/total/pages`；按具体 endpoint 适配，不能一律套模板 REST 分页 |
| 查询序列化 | 文档把部分 GET 查询声明为单个对象 DTO；扁平 query 与对象序列化必须经真实联调核实，不默认为任意一种必然正确 |
| 排序/筛选 | 只开放后端明确支持的全量排序/筛选；不能只排序当前分页却暗示全量有序，也不发送虚构 sort 参数 |
| 时间 | 按 endpoint 要求序列化 date-time、日期或统计天数；不把不同含义的时间参数统一猜测 |
| 数字 ID | 对 int64 标识核实真实值与精度；禁止精度丢失后再转字符串。必要时采用无损解析/字符串契约，未确认前登记缺口 |
| 请求取消 | 普通查询响应需防止乱序覆盖；区分主动取消与失败，主动取消不显示错误 |
| 重试 | 可重试已确认幂等的查询；创建、控制、发布、上传提交等写操作不自动重放 |
| 文件 | 独立处理 Blob/流、Content-Disposition、实际错误 JSON 和上传进度，不能把二进制套入普通 Result 解包 |

保留统一请求健康反馈，但不得把被取消的请求或合法业务拒绝误判为后端离线。并发登录失效统一收敛，避免重复通知和重定向风暴。

### 4.3 文档与实际差异

先按文档实现。仅在真实请求/响应、后端确认或其他可核实契约证明差异后集中适配，记录 endpoint、差异、验证日期和处理方式。旧代码仅是待验证线索，不能自动替代文档成为事实。没有证据的请求保持不可用，不探测写接口猜协议。

API 文档缺失的能力保留有权限用户的入口并说明不可用原因，进入接口缺口登记；其他已具备接口的功能继续。缺口与“无权限”“服务暂时离线”“真实空结果”“本期暂缓页面”必须分开呈现。

### 4.4 环境

使用可配置的同源代理，开发默认真实目标 `http://10.11.2.67:8888`，部署可覆盖。可延续 `APEX_DEV_PROXY_TARGET` 和 `VITE_API_BASE_URL` 等现有命名，代理前缀是否去除必须明确，使最终上游路径准确为 `/fms/v1/...`。

生产优先由同源反向代理转发，避免在业务组件硬编码 IP、端口和协议；HTTPS 页面不得连接硬编码 HTTP/WS。这里只确定后续联调目标，未声明本轮已访问、登录或验证该服务器。

## 5. 认证、软件授权与权限

1. 删除临时直通登录及本地伪造超级管理员信息。调用真实登录，使用返回的 `token/activated/user/roles/permissions/permissionsTree` 构建会话。
2. 保留真实 token 与登录返回权限的持久化体验，刷新页面或重启浏览器可恢复；不存密码。token、权限、页签和用户数据在退出、过期或切换账号时清理，多窗口同步退出。
3. 恢复持久化数据只恢复已登录的前端上下文，不代表服务端仍然认可 token；请求必须继续由后端鉴权，失效时清理并重新登录。
4. 不调用文档没有的刷新令牌、`/users/me` 或旧 `/fms/v1/auth/authorize/detail` 来伪装会话验证。后端新增契约前不实现静默刷新。
5. 旧实现对密码执行 MD5、Authorization 使用 Bearer，而文档只声明密码字符串且没有 securitySchemes；迁移需核实实际认证契约，在单一认证适配点保留已证实行为，不能把猜测写成正式协议。
6. 登录过期与软件未激活/授权失效分开处理。旧业务码 `1000000`、`1001000` 是代码证据，须在真实接口确认后映射。授权流程仅暴露后端允许的入口，不能把所有独立页面当成免鉴权公开页面。
7. 权限采用后端返回的菜单树与按钮码，保留旧有父子/祖先填充语义及角色分配的半选行为。菜单、路由直访、页内按钮和独立窗口均受控制。
8. 保留旧系统 `root`、`administrator` 特殊规则，集中管理；用户名应取真实登录返回的身份，不信任任意输入。普通用户严格按后端权限；权限管理等旧有超级管理员专属限制继续保留，后端是最终鉴权方。
9. 已登录权限可能滞后：收到权限拒绝立即阻止对应操作并提示重新登录获取权限，不伪造权限刷新接口，不因为前端按钮可见而绕过服务端拒绝。
10. 通常隐藏无权限的动作；只读编辑值保留可读呈现。接口缺口则对有权限用户显示禁用入口与原因，避免混淆两种状态。
11. 深链接登录回跳仅允许站内合法且有权限的目标。页签、草稿、列偏好和查询缓存不能在不同用户间串用。
12. 载具类型、数据库备份等旧路由未显式声明 access 的页面，需要核对原权限清单和后端实际资源，不把“未写 access”解释为公开访问，也不凭空创造后端权限码。

## 6. ApexTableReact 统一表格规范

### 6.1 接入边界

所有业务表格、弹窗表格、嵌套明细、编辑表格、报表明细和文件列表统一使用 npm `apex-table-react`。不保留 Ant Design Table/ProTable/EditableProTable，也不以自绘 HTML table 绕开要求。非表格的键值详情可以使用普通详情布局。

页面与业务组件直接使用 npm 包公开 API（`ApexTableReact` 组件、locale、官方列偏好适配器、插槽、ref 与诊断能力），**禁止对 ApexTableReact 做二次封装**：不建立包装组件、转发组件或统一表格入口组件（用户决策 2026-09-17，替代本文件此前版本的“薄业务适配层”方案）。允许的公共设施仅限不改变组件形态的资源与纯函数：五语言 locale 文案包、主题 CSS 变量映射、零基 `pageIndex`→`pageNo` 换算与行 ID 取值等纯函数工具，以及不包裹表格本体的独立状态块（统一空态/无权限/暂缓/缺口/离线呈现）；这些设施由各页面自行组合到 `ApexTableReact` 的 props 上。优先用公开 API 与插槽；能力不足时改成表格加抽屉编辑，保留业务效果。不修改组件库源码、不引用其 src、不把本地路径或 npm link 作为生产交付方式。

### 6.2 数据与交互

1. `request` 模式承接服务端分页/查询；Apex 的零基 `pageIndex` 与后端 `pageNo` 明确转换，返回 `data/rowCount`。实际接口若采用其他口径另行适配。
2. `data` 模式可以承载真实接口返回的有限完整集合和用户编辑中的草稿行；这不属于 mock。不得用硬编码业务记录填充页面。
3. 表格请求与页面查询取消信号协调，处理页签关闭、条件变化、主动刷新及乱序响应；失败不得返回空数组冒充成功。
4. 每行使用稳定业务标识，嵌套行区分实体/父级作用域；禁止数组下标造成选中、展开或编辑错位。
5. 默认选择当前页，翻页、改变筛选或失去权限时清理无效选择，不隐式积累跨页批量目标。失败批次的结果清单独立保留，重新选择时再次核验对象。
6. 列宽、顺序、显隐、密度按用户和 tableId 持久化，包含配置版本，支持恢复默认；列结构变化需迁移或失效旧设置。多环境共享 origin 时也需区分服务实例。
7. 查询条件、分页和展开状态仅在当前页签内保留，不默认跨浏览器重启保存；敏感筛选不自动写入 URL。实体详情链接仍使用必要的实体定位参数。
8. 筛选变化返回第一页；删除末页最后一条后回到有效页；总数必须来自真实响应，未知总数不能伪造成 0。
9. 虚拟滚动、固定列与展开行在窄窗口、隐藏后重新激活、抽屉/弹窗和嵌套表格中正确测量。小规模编辑列表可根据包能力关闭虚拟化，避免输入焦点或高度异常。
10. 行内编辑与抽屉保存共享表单校验和权限。失败保留用户输入，只有确认成功后更新保存基线；未知枚举显示原始值或明确未知状态，不映射为正常。

保留现有 Dock、顶栏、页签、窗口圆角、玻璃效果、开合动画、全局 token 及深浅主题。业务区采用紧凑工具栏和清晰表格，减少重复标题、嵌套卡片及装饰；表格与 antd 共用视觉变量。尊重减少动画设置，不能让装饰遮挡操作或损害可读性。

## 8. 多页签、草稿、查询与刷新

### 8.1 草稿与缓存

切换工作区页签保留内存草稿。未保存修改的页签不得被普通 LRU 自动淘汰；必要时限制新增缓存或提示处理已有草稿，不能静默丢弃。关闭、刷新当前页签、关闭其他/全部页签应统一检查脏状态。浏览器刷新/关闭使用浏览器允许的离开提示；浏览器终止等非正常退出不承诺恢复草稿。

退出登录清除草稿，不跨会话持久化。用户主动退出前可提示未保存修改；会话失效不允许继续以旧身份提交。请求失败清理远端展示数据的规则不要求删除尚未保存的用户输入。

### 8.2 实时查询

实时看板、车辆状态、服务器资源等需要实时性的页面，仅在工作区页签激活且浏览器文档可见时刷新。默认一次请求完成后约 5 秒发起下一次，不并发堆积；重新可见立即刷新，失败采用有上限的退避。具体可配置间隔及退避上限在实现中集中定义。

普通配置列表以进入、重新激活、操作成功后的自动查询为主，不提供手动刷新按钮，不为所有 CRUD 页面默认增加持续轮询。非表格区域失败后须有可见状态下的有限退避自动重查，表格使用内建重试。后台页签暂停轮询并保留最后快照，但重新激活后先刷新，影响现场的操作需先核验新状态。

一次查询真正失败：立即清空该请求对应的远端数据区域，显示错误；表格提供内建重试，其他区域通过可见自动重查恢复，暂停依赖这些结果的操作。保留筛选条件与用户草稿，不以空列表、零 KPI、“无告警”替代错误。主动取消不属于失败；多个独立数据区域可以各自显示成功/错误，不能捏造一个统一成功快照。

HTTP 查询已满足本期实时能力时不迁入旧全局调度监控 WebSocket。某个保留功能确有 WebSocket 依赖时，先落实独立契约、认证、重连与可见生命周期，文档缺口按统一政策处理。

## 9. 写操作、设备命令与一致性

普通保存直接提交；设备控制、任务取消、批量指令、地图发布推送、全量告警码覆盖、版本重启/回滚及其他破坏性操作按影响分级确认对象和结果。提交中防重复点击，非幂等请求失败不自动重放，也不做未经后端确认的乐观成功。

批量操作逐项显示成功、失败或结果未知。后端只返回整批结果时，不编造逐项成功；可以保留整批已接受状态，结合可用查询核实各目标。超时/断连不能直接认定失败或成功，先查实际状态，再让用户决定是否重试。没有状态查询能力时明确“无法确认”，不自动补发。

接口返回“命令已接受”不等于设备动作完成；展示阶段必须与接口实际语义一致。重启/回滚后连接断开可能是预期结果，也不能因此立即宣布成功；依靠真实可用状态查询或人工确认恢复。查询恢复不重放原命令。

多步骤保存优先采用后端已有批量接口。编辑时记录基线，保存前读取关键状态，有冲突提示重新加载，不自动覆盖。没有版本号/事务时，前端预检查无法消除检查到提交之间的竞争，规格不承诺原子性；记录已知限制和部分提交结果。

保留当前可达页面中的真实仿真功能，例如调用 `orderTask/mockDispatch` 的模拟分配，明确标注仿真、权限与目标。名称含 mock 的真实业务 API 不等同于前端 mock 数据。仅暂缓页面内的模拟停靠/充电入口不因存在 API 自动新增到其他页面。

## 10. 文件传输与长任务

1. 覆盖地图文件、车辆告警码、升级包、日志、数据库备份及当前可达的导入导出，不迁入暂缓录制回放的文件任务。
2. 切换工作区页签时继续传输，传输状态不能依赖被 `Activity` 清理的页面 effect。需要独立的传输生命周期，但本期不新增面向用户的全局任务中心。
3. 关闭承载页签时提示正在传输；能够真实取消的传输才提供取消，不可取消的服务端阶段应明确说明并保留追踪入口。普通查询的取消机制不能误杀上传下载。
4. HTTP 取消只代表客户端终止等待或传输，不能保证服务端已撤回操作；服务器处理可能已开始时标为结果待确认，禁止把 Abort 当作事务回滚。
5. 真实可获得总字节数时显示上传/下载百分比和字节数；否则只显示不确定进度。上传到 100% 仅代表传输完毕，服务端仍处理时显示“正在处理”。移除旧 `FakeProgressModal` 和计时器模拟百分比逻辑。
6. 成功必须依据业务结果或文件响应确认。错误响应为 JSON/文本时不能保存为伪文件；下载文件名依据真实响应，处理异常文件名并及时释放 Blob URL。
7. 文件类型、大小限制及覆盖规则按已确认接口契约；没有契约时不假装支持断点续传、后台断点恢复、服务端进度查询或取消。
8. 全量告警码上传明确覆盖影响；地图发布/推送与升级包处理区别于单纯文件传输，按相应权限和写操作规则执行。
9. 导出使用真实后端导出能力并传递受支持筛选。不把当前页数据导出伪装成全部结果；接口没有全量导出能力时显示缺口或明确当前页语义，不擅自拉完所有分页形成资源风险。
10. 大文件处理尽量避免重复复制进内存，采用后端契约支持的浏览器下载或流式方式；需要 Blob 的鉴权下载必须验证实际文件规模。没有真实大文件环境时记录该性能项待验收。

## 11. 工艺、地图依赖、统计与业务边界

### 11.1 工艺与关联资源

保留任务步骤、动作顺序、嵌套参数、主/子工艺控制和旧系统实际支持的 Cron 语法。Cron 有秒位及 `?` 等现有语义，不能随意改成普通五段表达式；时区、校验与提交值应匹配后端调度器。没有可核实的调度器语义时不显示猜测的下一次执行时间。

关联地图、车辆、节点、动作、驱动等资源失效、删除或不再可访问时：显示原有标识及不可用状态，禁止静默选择第一项替代；保存前校验必要关联。联动下拉使用真实接口，切换父级条件需清理或重新核验依赖字段，并防止旧请求结果覆盖新选择。

地图共享能力从必要组件抽取：只读渲染、平移缩放、选点、高亮及回填；按需加载并验证 React 19 兼容性。不为选点顺带引入整个地图编辑器、监控或回放模块。选点取消不修改原草稿，确认仅回填当前目标行，失效节点明确反馈。

### 11.2 指标口径

只使用真实 API 返回值。经文档核对后保留旧业务公式，集中放置纯计算与单位转换，图表/卡片/表格共用结果，并能展示统计口径。

已观察到旧车辆状态统计使用“每车 × 每状态”的时长记录，字段 `totalDurationSeconds` 单位为秒。迁移时需逐项验证单位、统计区间、状态集合、当天车辆数、利用率分母与日边界；不能直接照搬旧代码中的 `null ?? 0` 作为缺失数据策略。

| 情况 | 展示 / 计算规则 |
| --- | --- |
| 后端明确返回 0 | 正常显示 0 |
| 缺字段、null、未知分母 | 显示不可计算或 `—`，不得填 0 |
| 除零 | 显示不可计算，不显示 Infinity、NaN 或虚假 0% |
| 未知状态 | 显示可识别未知状态与原值；相关分组/分母不明确时不计算受影响指标 |
| 真实空结果 | 显示无数据，与查询失败分开 |
| 查询失败 | 清空该区域远端数据并显示错误；表格提供内建重试，其他区域通过可见自动重查恢复 |
| 前后周期不完整 | 标明样本/区间限制，不编造同比环比 |
| 重复或异常记录 | 按已确认业务键和聚合语义处理，不凭猜测去重、截断或补齐 |

统计天数、日期范围和分页控件只能提供接口支持的能力。例如仅接受统计天数的接口不能伪装支持任意起止日期筛选。旧图表可继续使用兼容的 ECharts，按需注册、释放实例并适应页签显示/隐藏，不迁入旧 mock repository。

### 11.3 时间口径

业务时间跟随后端部署时区，在页面明确显示。没有时区配置接口时通过环境/部署配置提供，缺省 `Asia/Shanghai`，不虚构查询 endpoint。使用者浏览器所在时区不能静默改变按天统计范围或 Cron 业务日期。

保留原始时间语义：带偏移时间正确转换；没有时区的字符串必须先确认后端解释方式。筛选范围起止是否包含边界、秒/毫秒单位和日期截断在对应服务中明确，避免同一时间不同页面显示不同业务日。

## 12. 零 mock 约束

必须移除运行路径内的 mock 服务、固定示例业务记录、随机统计、模拟请求延迟、伪成功响应、临时直通登录、假上传/下载进度和真实接口失败后的 mock fallback。

重点清理已发现的 `src/services/dashboard/dashboard.mock.ts`、`src/services/order-record/order.mock.ts` 及引用，同时检查旧统计模块的 mock repository、常量和演示分支是否被带入。禁止把空数组或全零对象作为错误时的成功响应返回。

允许静态的界面文案、枚举展示元数据、图标、品牌默认资源和用户尚未提交的表单草稿；这些不得伪装成服务端业务记录。真实后端仿真接口的响应属于真实业务数据，按已确认仿真范围处理。

本次验收不以 mock server、伪接口或预置假业务数据证明页面接入成功。真实后端不可用时明确记录“接口未验证”，展示真实错误，不提供离线演示数据替代。检查不能只搜索字符串 mock 后删除所有匹配，因为合法后端 `mockDispatch` 需要保留。

## 15. 验收标准与证据

### 15.1 验证方式

后续自动执行构建、类型与静态检查，以及真实只读接口验证。查询性质的 POST 应按实际业务性质归类，不能仅依据 HTTP 方法决定是否有副作用。涉及创建、删除、车辆控制、开关门、任务取消、地图推送、重启和回滚的验证，仅在专用测试环境或由现场人员执行，并保留证据；不以本次规格授权推断可以在默认现场目标上自动试发命令。

| D32 验收执行 | 自动编译/静态/真实只读，副作用操作专用测试环境或现场验收，留证据 |
| D33 本轮交付点 | 完整 SPEC，核对决策/范围/缺口/验收；本轮不迁移代码 |
| D34 完整国际化迁移 | 简体中文、英文、繁体中文、日语、韩语全部迁移并开放切换；缺失翻译回退简体中文并登记 |

## 17. 状态与后续变更管理

产品范围和主要取舍已通过访谈确定。接口安全头、密码编码、上传媒体类型、GET 对象序列化、精度、统计口径等保留为有明确处理策略的技术验证项，用户无需在本轮输入凭据、接口细节或额外文字。

后续实现发现新缺口时，先按本规格保留不可用入口并登记；需要改变已确认范围、引入后端修改、调整权限语义或扩大现场副作用验证时，再提出具体选项。新增 API 文件应记录新哈希并评估受影响 operation，不能只因为文件名相同就假定兼容。

本规格的“已确认”表示用户已确认产品决策；不表示所有接口已真实联调，不表示旧后端已经具备缺失能力，也不表示页面迁移已经完成。

## 18. 国际化完整迁移（追加确认）

### 18.1 语言范围与资源基线

国际化是每个模块迁移的组成部分，不能只迁移菜单、登录和表格列标题，也不能全部推迟到页面交付之后。本章将先前中英文要求扩展为五语言，优先于前文及旧文档中的较窄语言范围。

| 语言 | 统一语言标识 | 旧资源文件 | 本次勘察的顶层 key 数 |
| --- | --- | --- | --- |
| 简体中文 | `zh-CN` | `C:\code\dd\src\locales\zh-CN.json` | 2092 |
| 英文 | `en-US` | `C:\code\dd\src\locales\en-US.json` | 2092 |
| 繁体中文 | `zh-TW` | `C:\code\dd\src\locales\zh-TW.json` | 1478 |
| 日语 | `ja-JP` | `C:\code\dd\src\locales\ja-JP.json` | 1478 |
| 韩语 | `ko-KR` | `C:\code\dd\src\locales\ko-KR.json` | 1478 |

上述为顶层 key 数，不代表可见文案总数、翻译准确率或完整覆盖率。须解析嵌套资源并结合实际调用建立映射，不能以数量相同判定无遗漏。旧 `SPEC_i18n.md` 中的早期资源规模描述不替代当前文件事实。

保留旧系统已有的五语言译文并迁入目标项目资源体系，补充本次迁移新增的公共交互文案。暂缓页面的已有语言资源应保留对应关系，但不因此实现暂缓页面。与未迁移历史页面有关的资源可以独立保留，不需要加载到本期业务页。

允许缺失翻译回退简体中文，不把本期范围扩大成必须人工补齐所有旧缺失译文；但不能故意忽略已有译文而依赖回退。建立缺失清单，至少记录语言、命名空间、中文 key、所属页面和处理状态。

### 18.2 国际化架构迁移

1. 统一使用目标项目 `react-i18next`/`i18next`，替换旧 `@umijs/max` 的 `useIntl`、`formatMessage`、`setLocale` 及封装它们的 `useI18n` 依赖，不并存两套运行时。
2. 延续中文文案作 key、按业务命名空间加载的目标规范。通用、菜单、认证、车辆、地图、工艺、设备、统计、系统等资源明确归属，维护“旧 key → 新命名空间/key”映射。旧 Umi 菜单嵌套 key 按目标路由元数据重新映射，不机械复制嵌套结构。
3. 扩展 `SUPPORTED_LANGUAGES`、语言类型、懒加载器和 locale 映射，覆盖五语言；不能继续使用只支持 `en-US` 的加载表。路由、独立详情及共享弹窗声明或预加载自身使用的命名空间。
4. 修正 `normalizeLanguage`：精确保留 `zh-TW`、`ja-JP`、`ko-KR`，不能继续把所有 `zh-*` 归为简体，也不能把日/韩语归为默认语言。兼容旧系统实际使用的语言代码；未知代码才按约定回退。
5. 现有简体中文采用“中文 key 即文案”且无资源文件。对旧简体资源必须核对 key/value：值与 key 相同可继续省略；不同的值、历史别名或嵌套语义需显式迁移，不能因使用中文 key 而丢失正确译文。
6. 将旧 React Intl 的 `{name}` 插值转换为 i18next 对应的 `{{name}}`，同步更新资源和调用参数。对 ICU plural/select、富文本、转义花括号等单独检查，不能全局盲目替换。非翻译业务 JSON、Cron、模板表达式中的花括号不得被改动。
7. 保留数量、单位、变量和上下文完整性，避免用零散词语拼接句子造成英文/日语/韩语语序错误。相同中文在不同业务含义下可拆命名空间或明确上下文，统一 AGV、任务、工艺、节点、交管、载具等术语。
8. 不在模块加载时把枚举、列定义、图表配置和按钮列表一次性翻译成固定字符串；语言切换后重建或动态读取，缓存页签恢复时不得显示上一种语言。

### 18.3 必须覆盖的可见文案

- 登录、软件授权、MacOS 顶栏/Dock、菜单、页签、面包屑、窗口操作、个人入口及错误页。
- 页面标题、筛选、表单标签与帮助、占位符、校验提示、确认弹窗、通知、Tooltip、空态、错误态和接口缺口说明。
- 任务/车辆/设备/告警状态与动作枚举、权限树的前端展示标签、批量结果、不可用原因、真实仿真提示。
- ApexTableReact 的表头、工具栏、分页、列设置、固定与排序提示、密度、行选择、展开、编辑器、重试及可访问名称。
- 图表标题、轴标签、图例、Tooltip、统计单位、指标口径、日期区间和无数据/不可计算提示。
- 工艺、Cron 编辑器、地图选点及共享组件、嵌套明细、上传下载、服务端处理中和不确定结果提示。
- 新增的草稿保护、关闭页签提示、权限更新提示、传输提示及三个暂缓页面说明。

用户填写的名称、原始业务标识、日志内容、文件内容及服务器返回的业务原文不做猜测翻译；缺少可映射枚举时保留原值并提供本地化的未知状态说明。API 状态码、权限码和枚举提交值保持原协议，不提交翻译后的标签。

### 18.4 第三方组件、日期与切换行为

Ant Design `ConfigProvider` 的 locale、表单默认校验、Modal/通知上下文、DatePicker、Select 等与应用语言同步。通过 ApexTableReact 当前公开的 locale/插槽能力提供五语言文案，不假设包默认 locale 已覆盖全部目标语言；必要时在业务侧映射，遵守不修改组件库的决定。

同步 dayjs locale、`document.documentElement.lang`、Intl 数字和日期展示；语言只影响呈现格式，不改变第 11.3 节确定的部署时区、业务日期、Cron 语义和接口数值。坐标、精度、十进制输入等必须区分显示格式与协议编码，避免将千分位或本地化小数符号直接提交给接口。

登录页与已登录外壳均提供五语言选项。使用当前持久化语言配置作为唯一运行时来源；同源环境存在旧 `umi_locale` 且没有新配置时，可以执行一次兼容迁移，不能长期维护两个相互竞争的语言状态。不同 origin 的旧存储不可读取，不假定可自动迁移。

切换时先加载基础资源与已打开页签所需命名空间，再整体切换；不通过整页刷新丢失工艺或表单草稿，不重置筛选和当前实体。数字/日期校验提示更新语言，但不修改用户输入值。资源加载失败保留当前可用语言并给出可读反馈；单个译文缺失则使用简体中文回退并登记。

独立窗口首次打开时读取相同的持久化偏好，并加载自身资源；退出登录后的语言偏好可保留，不能把语言切换当成重新授权。长文本、日语/韩语字体和繁体中文不能造成按钮截断、表头不可读或图表图例遮挡。

### 18.5 接口语言与服务端文案

统一请求入口使用当前语言提供已证实的 `Accept-Language`，包括文件上传等特殊请求路径，不能继续从旧 `umi_locale` 单独读值。记录后端支持的语言代码和回退行为；后端不支持某语言时不能声称错误消息和导出文件也已完整翻译。

语言切换后，仅对依赖服务端语言的只读展示适当重新查询，且防止旧语言响应覆盖新语言数据；控制命令、保存、导入、发布、重启等写请求不得因切换语言自动重发。进行中的传输继续运行，进度标签可以更新，已开始的服务端文件任务不假装被重新本地化。

已有稳定业务码可以映射为本地化提示，并保留必要的后端详情；无法映射的消息保留服务端原文，不隐藏诊断信息。后端生成的报表/Excel/PDF/日志文件内部文本属于后端能力边界，支持情况单独记录，前端只保证自己的按钮、结果提示与可控展示文案。

如果后续保留功能确需 WebSocket，语言参数按已验证消息/握手契约处理，不为了国际化迁回暂缓监控页面的全局 WebSocket。
