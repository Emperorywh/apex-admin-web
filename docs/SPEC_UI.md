## 1. 背景与目标

当前界面功能完备（用户确认「功能没问题」），但视觉停留在 antd v6 默认观感：浅色侧边栏 + 亮蓝高亮、浏览器卡片式页签、头部与设置抽屉排版粗糙（标签挤压换行）、表格区域大片空白。用户评价「很丑」。

**目标（已定）**：在**零功能变更**前提下，将界面升级为「现代极简（Linear/shadcn 风）× Ant Design Pro 经典企业风」融合的现代后台观感——前者提供留白、细边框、克制色彩与精致微交互，后者保证企业场景的稳重与信息密度。

**非目标（已定）**：

- 不新增任何功能（无全局搜索、无通知中心、无新设置项）。
- 不重做业务页面内容区（用户/角色/菜单管理等页面只继承全局 token 变化，不逐页重设计）。
- 不做移动端响应式适配（桌面优先，移动端仅保证不白屏不错位，与现状一致）。
- 不引入 Playwright 截图视觉回归（视觉质量靠人工走查把关，E2E 只断言功能与结构）。

- settings 切片字段：零新增 → 无持久化版本迁移（主规格 §8）。

- 业务页面信息架构、演示数据、API 契约。

## 3. 设计原则（已定）

1. **Token 优先，少量覆盖**：以 ConfigProvider `token` / `components` 配置承载绝大部分变化；壳层自绘部分用 CSS Modules + antd token/CSS 变量，不做深度自绘组件库。
2. **细边框优先于阴影**：用 1px 中性边框划分层次，阴影仅在浮层（下拉、抽屉、Popover）使用。
3. **小圆角 + 紧凑密度**：`borderRadius` 4–6px 区间；表格/列表/表单维持企业级信息密度，不追求消费级宽松。
4. **双主题同等精品**：亮/暗不是简单算法反色，两套各自独立调优（侧边栏灰阶、边框明度、选中态、阴影分别取值）。
5. **微过渡即可**：仅 hover / 展开 / 选中切换的 150–250ms 过渡；无页面入场动效、无页签切换动效。
6. **全组合美观**：设置抽屉的现有组合能力（侧边/顶部 × 亮/暗 × 任意主题色）在新设计下都必须成立，不允许只在默认组合下好看。

## 4. 设计令牌基线

### 4.1 全局 token（默认，实施时以实测微调并回写本文档）

| Token | 取值方向 | 说明 |
| --- | --- | --- |
| `borderRadius` | 6（小组件 4） | 当前 antd 默认 6，统一收紧层次：按钮/输入 6、卡片/弹层 8 上限 |
| `colorBorder` / `colorBorderSecondary` | 偏浅中性 | 亮主题细边框为主分隔手段 |
| `padding` / `margin` 系 | 紧凑 | 内容区页边距、卡片内边距统一收敛 |
| `boxShadow*` | 仅浮层使用 | 卡片、表格容器去阴影化 |
| `controlHeight` 系 | 保持 antd 默认 | 不牺牲可用性换密度 |

> 阶段一实施回写（2026-08-17 实测定稿）：`borderRadius: 6` 显式锁定（SM 4 / LG 8 由 antd 派生）；`colorBorder`/`colorBorderSecondary` **维持算法默认**（亮 `#d9d9d9`/`#f0f0f0`、暗 `#424242`/`#303030`，实测已属偏浅中性且亮暗各自正确，不再字面覆盖）；阴影维持算法默认（仅浮层有阴影，满足「细边框优先」）；`controlHeight` 默认；`Card.paddingLG` 24→20、`Table.cellPaddingBlock/Inline` 16/16→12/16 承载「紧凑密度」。

### 4.2 组件级覆盖（已定）

通过 ConfigProvider `components` 字段承载，不落硬编码样式：

- `Menu`：选中项背景 = 主题色 8–10% 透明度浅底 + 2px 左侧主题色指示条；item 圆角 6px；分组间距加大；折叠态（icon only）选中指示条保留。
- `Tabs`（仅页签栏，见 §5.3）：页签栏不用 antd Tabs 组件呈现，改 CSS Modules 自绘（下划线极简式 antd Tabs 无法低成本达成）；业务页内若使用 antd Tabs 保持 token 默认。
- `Table`：表头去灰底改中性浅底/细下边框，行高紧凑，行 hover 浅底；内容区改造仅限 token 级，不改列结构与交互。
- `Button` / `Input` / `Select`：圆角与边框 token 生效即可，实心主按钮保持主题色。
- `Drawer` / `Dropdown` / `Tooltip` 等浮层：保留阴影 token。

> 阶段一实施回写（2026-08-17 实测定稿）：`Menu` 落盘为 `itemBg/subMenuItemBg: transparent`（透出侧边栏中性灰底；弹层子菜单仍走 `popupBg` 浮层底色）、`itemBorderRadius/subMenuItemBorderRadius: 6`、`itemMarginInline: 8`、`itemMarginBlock: 6`、`itemHeight: 38`、`itemHoverBg: colorFillTertiary`、`itemSelectedBg: colorPrimaryBg`（即主题色 8–10% 浅底，随主题色/亮暗派生）、`itemSelectedColor: colorPrimary`、横向 `horizontalItemSelectedBg: colorPrimaryBg` + `horizontalItemHoverBg: colorFillTertiary` + `horizontalItemBorderRadius: 6` + `activeBarBorderWidth: 2`（指示条置底）；左侧 2px 指示条 token 无法表达，由 `SideMenu.module.css` 的 `::before` 承载（内缩 8px 小圆角竖条，折叠态保留），选中叶子的祖先目录标题经 CSS 着主题色。`Table` 落盘为 `headerBg: colorBgContainer`（去灰底、亮暗各自派生）+ 行高紧凑（`cellPaddingBlock: 12`）+ 行 hover 浅底（`rowHoverBg` 维持算法默认 `colorFillAlter`）。`Button/Input/Select/Drawer/Dropdown/Tooltip` 实测无需覆盖，维持算法默认。全部取值经 `theme.getDesignToken` 按当前算法+主题色派生，无色值字面量。

### 4.3 色值纪律（红线，主规格 §10.2 不变）

- 色值字面量仍只允许出现在 `src/config/theme.ts`；CSS Modules 与 TSX 只能消费 `theme.useToken()`、`var(--ant-*)` 或 theme.ts 导出值。
- 新设计需要的中性灰阶（侧边栏底、hover 底、分隔线）**优先从 antd token 派生**（`colorBgContainer` / `colorFillQuaternary` / `colorBorderSecondary` 等，亮暗算法各自派生正确取值）；token 无法表达的少量取值，以具名导出收敛进 theme.ts。
- 侧边栏为「随主题的中性灰」（已定）：亮主题 ≈ `colorFillQuaternary` 级浅灰，暗主题 ≈ 深炭灰，均由算法 token 派生，与内容区形成轻对比。

### 4.4 预设主题色板刷新（已定）

8 个预设全部重新精选为现代色板，默认主题色允许更换。建议候选（实施时**必须逐项通过现有 `contrastRatio ≥ 3` 白字对比度校验**（theme.test.ts 机制），不达标者微调明度后回写本文档）：

| key | 建议色 | labelKey |
| --- | --- | --- |
| indigo | `#4f46e5` | 靛蓝（**新默认**候选） |
| azure | `#1677ff` | 湛蓝 |
| emerald | `#059669` | 翡冷翠 |
| violet | `#7c3aed` | 紫罗兰 |
| sunset | `#ea580c` | 落日橙 |
| crimson | `#dc2626` | 绯红 |
| teal | `#0d9488` | 青碧 |
| magenta | `#db2777` | 品红 |

兼容性（已定）：老用户 localStorage 持久化的 `colorPrimary` 为任意 hex，换预设不影响其合法性；`DEFAULT_COLOR_PRIMARY` 变更只影响首次安装用户；预设条目 key/labelKey 变化需同步 en-US 资源。

> 阶段一实施回写（2026-08-17）：上表 8 色按建议值原样落盘（indigo 为首项即新默认），逐项通过现有 `contrastRatio ≥ 3` 白字对比度校验（最低为 azure ≈4.10），无需明度微调；en-US 资源同步为 靛蓝 Indigo / 翡冷翠 Emerald / 紫罗兰 Violet / 落日橙 Sunset / 品红 Magenta，移除旧条目 翡翠绿/酱紫/日暮橙/洋红/鎏金。

## 5. 壳层组件设计

### 5.1 侧边栏 SideMenu（痛点区，已定）

- 底色：随主题中性灰（§4.3），与内容区以 1px `colorBorderSecondary` 分隔，无阴影。
- 选中态：主题色 8–10% 浅底 + 左侧 2px 主题色指示条 + 主题色文字/图标；hover 态为中性浅底。
- 层级：子菜单缩进与连接线按 antd Menu token 精调；菜单项行高紧凑。
- 品牌区：保留现有文字品牌「通用后台管理模板」+ 图形标，仅精修排版、间距与折叠态呈现（默认）。
- 折叠（icon only）态：选中指示条保留，tooltip 展示标题，交互不变。
- 顶部布局对应物：TopMenu 使用同一套选中态语言（浅底 + 主题色文字；横向场景指示条置底，默认）。

### 5.2 头部 Header（痛点区，已定）

- 元素构成不变：折叠触发器、面包屑（受 `breadcrumbEnabled` 开关控制）、右侧工具组（演示模式标记 / 全屏 / 语言 / 主题 / 用户头像菜单 / 设置入口）。
- 重排要点（默认）：工具图标统一为 Lucide 16–18px、统一 hover 浅底圆角容器；头像与用户名间距收紧；头部底色 `colorBgContainer` + 底部 1px 细边框。
- 演示模式标记（黄色 Tag）保留语义色，样式精修即可。

### 5.3 页签栏 TabsBar（痛点区，已定）

**下划线极简式**：

```
  仪表盘    菜单管理 ✕    角色管理
           ▔▔▔▔▔▔▔▔
           ↑ 当前页 2px 主题色指示线
```

- 无框无底：页签为纯文本 + 图标，当前页文字 `colorText` + 底部 2px 主题色指示线，非当前页 `colorTextSecondary`。
- 关闭按钮：仅 hover（或当前页）显现，避免视觉噪声；affix 页签（仪表盘）无关闭按钮，行为不变。
- **交互零变更**：dnd-kit 拖拽排序、右键上下文菜单、横向溢出滚动、关闭/关闭其他/关闭右侧等全部保留。
- 过渡：指示线与文字色 150–200ms 纯 CSS transition。
- 与页签缓存的边界（红线）：样式与动效**只依赖 CSS 与 React 渲染**，不得引入依赖挂载 Effect 的 JS 动效——Activity 隐藏页会被清理全部 Effect（主规格 §9）。

### 5.4 面包屑 Breadcrumb（默认）

- 开关行为不变；分隔符、末级不可点、图标对齐精修；字号随根 rem 基准排版不破版。

### 5.5 设置抽屉 SettingDrawer（痛点区，已定）

- 修复现状标签被挤压换行的问题：分组（主题 / 布局 / 界面元素）带小标题与充足间距，控件标签与控件分行或保证最小宽度。
- 全部设置项与即时生效行为不变；自定义取色器与对比度提示（主规格 §11.3）保留。
- 预设色板选择器展示刷新后的 8 色（§4.4）。
- 抽屉本身按 §4.2 浮层规范呈现（保留阴影）。

## 6. 登录页（已定）

**左右分栏版式**：

- 左侧品牌区（约占 40–50%）：产品名与图形标、一句标语、装饰性几何（渐变/网格纹理，由主题色 token 派生，亮暗主题各自适配）；demo 模式下展示演示账号提示（admin / viewer，密码任意）。
- 右侧登录卡：欢迎语 + 账号/密码表单 + 登录按钮，居中于右半区；卡片去重阴影，细边框或无框（默认）。
- 表单行为、登录状态机、错误反馈（主规格 §6/§7）零变更。
- 小窗口降级：桌面优先，窄屏允许品牌区隐藏退化为单列（与「桌面优先」一致，默认）。

## 7. Dashboard 视觉重排（已定）

- 信息架构与内容模块**不变**，仅应用新 token：卡片统一细边框小圆角、间距节奏收紧、图表配色从 token/主题色派生。
- ECharts 只从 `echarts/core` 按需注册的红线不变（主规格 §2）；图表用色禁止字面量，经 useToken 或 theme.ts 导出取值。

## 8. 全局反馈页与加载态（默认）

- 403 / 404 / 路由错误页（PageErrorBoundary 兜底）、路由加载 fallback 统一套用新视觉：居中留白排版、主题色点缀、Lucide 插画级图标。
- 行为（重试、返回、错误上报边界）零变更。

## 9. 动效规范（已定）

- 时长 150–250ms，`ease` / `ease-out`；仅用于 hover、展开/折叠、选中切换、抽屉与浮层进出。
- 无页面入场动效、无滚动动效、无装饰性循环动画。
- 全部过渡以纯 CSS transition 实现；禁止引入 JS 动画库（无新依赖红线）。

## 10. 双主题与启动镜像（已定 + 红线）

- 亮/暗两套独立调优：侧边栏灰阶、边框明度、选中态浅底透明度、浮层阴影分别取值并经人工走查确认。
- **启动镜像同步（红线）**：`index.html` 内联启动脚本（主规格 §8.3，读 `apex_boot_theme` 预置 `data-theme` 与背景）必须与新壳层背景策略保持一致——新设计若改变首帧背景（如侧边栏灰底区域），启动脚本写入的 `html/body` 背景同步更新，保证整页刷新无首帧闪变。Redux 仍是运行时单一数据源。
- 跟随系统、手动切换、系统偏好监听的行为零变更（主规格 §10.2）。

## 11. 字号 / 字体族约束（已定，随主规格 v1.6 修订）

- 字体不提供设置项（主规格 §10.1）：基准字号固定 16px（根 rem 基准 html font-size 与 antd fontSize 同值），字体族固定系统字体栈；壳层尺寸一律使用 rem 或 antd token，禁止散落固定 px。
- 不引入 Web 字体文件（无新依赖/资产红线），继续使用系统字体栈。

## 12. 测试影响与验收

### 12.1 存量测试（已定）

- **允许破坏并同步修复**：壳层 DOM 结构重排导致的 E2E 选择器与布局单测（BasicLayout/TabsBar/SettingDrawer 等）断言更新，属于本次改造的一部分，不视为回归。
- E2E 用例总数与 §16.3 映射关系保持有效；选择器优先使用语义化（role/label）或稳定 data-testid，降低下次视觉迭代的维护成本（默认）。
- 覆盖率门禁不变（主规格 §16.3）：改动涉及的 `src/router/`、`src/services/`、`src/store/`、`src/utils/`、`src/features/**/hooks/` 仍须 ≥80%。
- `pnpm check`（structure → lint → typecheck → test → build）与 `check:demo-off` 全绿是每阶段交付前提。

### 12.2 人工走查矩阵（已定）

每阶段交付前按矩阵抽查，确认「全组合美观」：

- 亮 / 暗 × 侧边 / 顶部布局；
- 语言 zh-CN / en-US 抽查（新文案 key 必须有 en-US 资源，主规格 §12）；
- 预设色板至少 3 个非默认色抽查选中态/实心按钮可读性；
- 页签栏：多页签横滚、拖拽排序、右键菜单、affix 页签；
- 登录页亮暗两态。

### 12.3 验收标准

- 用户截图走查确认壳层、登录页、Dashboard 达到预期观感（两阶段各一次）。
- 全量 E2E（chromium 全量 + firefox/webkit 冒烟）通过。
- 无新增依赖；`src/config/theme.ts` 之外无色值字面量（structure/lint 门禁）。
